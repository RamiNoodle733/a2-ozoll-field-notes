Agent automation checklist.

A small review sheet for a system that should keep working after the demo ends. Copy it into an issue or print this page.

Before it runs

  1. One job: What useful result should this automation produce?
  2. Source: Where does its input come from, and can the source be trusted?
  3. Budget: What is the maximum number of runs, model calls, tokens, and dollars per day?
  4. Permission: What data and accounts can the agent access? Are those privileges necessary?
  5. Idempotency: If the job runs twice, will it duplicate posts, messages, charges, or files?

When it fails

  1. Detection: What observable signal says the job failed?
  2. Safe stop: Does it stop before a failed step causes more damage?
  3. Rollback: Can it restore a known good version or leave the old process running?
  4. Recovery: Is the exact repair action shown where the user will see the error?
  5. Evidence: Can you prove the result reached the intended destination?

Before public output

  1. Claims: Can every first-person result be tied to an actual run or artifact?
  2. Review: Is there a clear approval boundary for public claims or paid offers?
  3. Feedback: Track the useful outcome: saved time, subscribers, qualified leads, or revenue.

Start with one repeatable workflow. Add more agents only when a measured bottleneck calls for one.
